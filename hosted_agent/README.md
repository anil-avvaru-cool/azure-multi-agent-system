# Foundry Hosted Agent Scaffold

This directory is intentionally close to empty. `azure.yaml`, `agent.yaml`,
`.agent_configs/`, and the provisioning infra-as-code are generated by the
`azd` CLI itself — hand-writing them ahead of time risks producing files that
don't match what the installed `azd`/`microsoft.foundry` extension version
actually expects, which is exactly the kind of workaround-instead-of-root-cause
this platform avoids.

## Generate the scaffold (provisioning step 4 — run with confirmation)

```bash
# one-time, if not already installed
curl -fsSL https://aka.ms/install-azd.sh | bash
azd ext install microsoft.foundry

# from this directory
azd ai agent init -m https://github.com/microsoft-foundry/foundry-samples/blob/main/samples/python/hosted-agents/agent-framework/responses/01-basic/agent.manifest.yaml
```

This generates `azure.yaml`, `agent.yaml`, `.agent_configs/baseline/`, an
evaluation dataset, infra-as-code, `.env`, and `.vscode/` in this directory,
scaffolded from Microsoft's basic Agent Framework + Responses-protocol sample
— the same protocol `fnol-claims-agent`/`underwriting-quote-agent` use per
CLOUD_ARCHITECTURE_AZURE.md §5.

## After scaffolding

Point the generated `agent.yaml`'s entrypoint at
`agents/policy_qa_agent/agent.py`'s `build_agent`/`run` (adjust the exact
wiring to whatever entrypoint shape the scaffold expects — confirm against the
generated file, don't assume). Then:

```bash
azd up      # first deploy: provisions Foundry project, model deployment,
            # container registry, App Insights, managed identity, and deploys
azd deploy  # subsequent code-only redeploys
```

Each of these creates or changes real, billable Azure resources — run one at a
time with confirmation, per this repo's operating posture.
